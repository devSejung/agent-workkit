# 한 번의 15분 사전체험

**명시적으로 사전체험 점검을 요청한 경우에만 사용한다. 본시험의 기본 세팅은 START.md를 따르며 이 문서를 자동으로 읽지 않는다.**

목표는 **작은 수정 → 저장 → 실행 확인 → 로컬 이력 보존**을 실제로 해보고, 사용자가 **체험 종료 → 예시 서술형**까지 확인하는 것이다. 도구함 clone이 막혀도 작은 실행 점검을 포기하지 않는다. 접속·시작·종료는 응시자가 직접 한다. AI가 대신 조작하지 않는다. 최신 공식 안내와 체험에 허용된 작업 범위가 우선한다.

## 세팅 직후: 이 표부터 보여주기

사전체험 맥락이 명시된 상태에서 사용자가 “세팅해”라고 하면 아래 표를 채워 **즉시 대화에 출력**한다. 파일에만 저장하지 않는다. 이미 확인한 항목만 실제 상태를 쓰고, 나머지는 `미검증` 또는 `허용 확인 필요`로 표시한다. 이 표는 계획이며 실행 성공의 증거가 아니다.

| 우선 | 꼭 확인할 것 | 지금 상태 | 바로 할 일 / 실패 시 대안 |
| --- | --- | --- | --- |
| 필수 | OS·셸·제공 Codex·작업 위치 | | OS 종류·사용 셸, CLI 버전·도움말과 과제/도구함 경로 확인. 업데이트하지 않음 |
| 필수 | 공개 준비물 가져오기 | | 실제 파일·revision 확인. 실패하면 허용된 아카이브 → raw START.md → 최소 요청 |
| 필수 | 지침 적용 | | START.md 경로를 명시해 읽고 핵심 경계 확인. 자동 발견에 의존하지 않음 |
| 최우선 | 작은 수정 → 저장 → 실행 | | clone 실패와 별개로 허용된 연습 작업 하나를 저장하고 실제 결과 확인. 제공 파일 전후 diff/해시 비교 |
| 웹이면 필수 | 실제 포트·바인딩 | | 제공 설정·빈 포트 확인 후 서버 실행. 실제 listen 포트와 0.0.0.0 바인딩 필요 여부 확인 |
| 웹이면 필수 | 내장 Browser 수동 버튼 확인 | | 사용자가 직접 열어 버튼·입력·결과 확인. HTTP 응답과 UI 확인을 별도 판정 |
| 필수 | 결과 판정 | | 기대와 실제를 대조. 실행하지 않은 항목은 미검증; 종료 코드 0만으로 통과시키지 않음 |
| 필수 | 로컬 Git 관리 | | status/diff로 기존 변경 구분, 자신의 검증된 작은 변경만 로컬 커밋. push는 시도하지 않음 |
| 중요 | 내부 이미지 전달 방법 질문 | | 캡처를 시도하지 말고 허용된 내부 전달 방법을 공식 창구에 질문. 미확인이면 텍스트·수동 설명 |
| 선택 | 브라우저 자동 테스트 | | 해당 방식의 허용·가용성 확인. 가능할 때 보조 검증으로 사용하며 캡처는 하지 않음 |
| 종료 전 | 재시작 방법과 남은 문제 | | 아래 요약표 출력. 체험 파일·설정이 유지된다고 가정하지 않음 |
| 마지막 | 체험 종료 → 예시 서술형 | | 사용자가 직접 이동해 안내·문항 형식·입력 및 완료 절차 확인. AI·복사·붙여넣기 사용 안 함 |

표 아래에는 다음 한 줄을 보여준다: **“계속하려면 ‘사전체험 점검해’. 남은 시간이 짧으면 함께 알려주세요. 끝낼 때는 ‘지금까지 요약해’라고 하면 됩니다.”** 세팅 요청만 받았다면 여기서 임의의 과제 수정을 시작하지 않는다.

항상 함께 알린다: **사전체험·본시험에서는 모든 push·원격 쓰기·외부 업로드 금지. 금지를 시험하려고 전송을 시도하지 않음.** OS나 네트워크 수준의 차단을 설치했다고 주장하지 않는다.

## 점검 요청을 받으면 진행하기

“사전체험 점검해”라는 요청을 받으면 허용된 독립 점검부터 수행한다. 이미 확인한 가져오기·지침 적용은 반복하지 않는다. 사람의 조작이나 공식 허용 확인이 필요한 항목만 구체적으로 남긴다. 실제 과제의 필수 파일을 실험용으로 덮어쓰지 않는다.

| 단계 | 권장 배분 | 실제로 할 일 |
| --- | --- | --- |
| 환경·가져오기 | 최대 3분 | CLI·쓰기 범위·가져오기 확인. 실패를 반복하지 않고 작은 실행으로 이동 |
| 작은 수정·저장·실행·로컬 Git | 약 6분 | 최소 변경과 실제 실행, 웹이면 포트·바인딩 및 사용자의 내장 Browser 버튼 확인 |
| 이미지 전달 방법 질문·남은 점검 | 약 1분 | 허용된 내부 전달 방식을 질문. 캡처를 직접 시도하지 않음 |
| 요약·다음 단계 안내 | 약 1분 | 요약표 출력, 사용자가 직접 종료·예시 서술형으로 이동하도록 안내 |
| 체험 종료·예시 서술형 | 나머지 약 4분 확보 | 사용자가 제공 절차에 따라 직접 확인. 화면이 별도 시간인지도 안내에서 확인 |

사용자가 알려준 남은 시간이나 제공 환경의 종료 시각이 있으면 그것을 기준으로 한다. 이 문서를 읽은 시점을 체험 시작으로 단정하지 않는다. 남은 시간을 모르면 필수 순서로 짧게 진행하고 결과를 단계마다 갱신한다. 종료 요청이 오면 새 작업을 시작하지 말고 확인된 결과부터 즉시 출력한다.

- 가져오기 같은 실패를 반복하며 시간을 쓰지 않는다. [대안](environment.md)으로 전환해 작은 실행과 정리 시간을 남긴다.
- **clone이 막혀도 작은 수정 → 저장 → 실행 확인은 해본다.** 도구함 읽기 성공과 제공 환경에서 코드를 저장·실행할 수 있는지는 별개다. 모든 가져오기가 막히면 제공 README·코드·실행 설정만으로 허용된 연습 작업을 진행한다. 세팅만 요청한 경우에는 실행 계획 표만 출력한다.
- 작은 작업은 체험 범위에서 허용된 것으로 고른다. 별도 샘플이 허용되면 그곳을 쓰고, 아니면 제공된 체험 작업의 작은 단위만 수행한다.
- Git의 기준 상태를 먼저 확인한다. 기존 파일의 전후 diff/해시를 비교하고, 의도한 코드 변경과 뜻하지 않은 변경을 구분한다. [로컬 Git 절차](../playbooks/implement.md)에 따라 자신의 변경만 커밋한다. 사용자 변경·개인 기록을 함께 커밋하지 않는다.
- 확인한 경로·검증 명령·실제 출력·커밋 ID는 체험 환경 안에 기록한다. 모든 언어·도구를 조사하거나 설치하지 않는다. 작업과 무관한 기능 탐지는 생략한다.
- 웹이면 [포트·내장 Browser 확인](environment.md#웹-실행-포트와-내장-browser)을 따른다. 사용자에게 열 주소, 직접 누를 버튼/입력, 예상 결과를 한 줄씩 알려준다. 아직 사용자 확인이 없으면 Browser는 미검증이다.
- 먼저 **“허용된 내부 이미지 전달 방법이 있나요? 있다면 제공 Codex에 전달하는 절차는 무엇인가요?”**를 공식 안내·질문 창구에서 확인하도록 안내한다. 캡처 도구·스크린샷 명령을 시도하지 않는다. 안내된 방법이 없으면 텍스트·사용자의 수동 설명으로 진행한다.
- push 가능 여부는 **실행 시험하지 않는다**. 이미 금지된 작업이다. 실제 체험 결과·수정물·로그·화면을 저장소로 보내지 않는다.

## 종료 전: 환경 확인 표를 반드시 출력하기

사용자가 이후 준비를 도와주는 AI에 결과를 알려줄 수 있도록 **일반적인 환경 호환성만** 짧게 정리한다. 표를 파일에만 저장하지 말고 화면에 바로 출력한다. 각 셀은 한 문장 이내, 개선 제안은 최대 3개로 제한한다. 실제 경로·명령·로그·커밋 ID를 담은 상세 기록은 체험 환경 안에만 둔다.

**이 표는 공유 허가 자체가 아니다.** 일반 환경 정보의 공유가 공식적으로 허용되는지 구분하고, 미확인이면 `공유 범위 미확인 — 전달 보류`라고 표시한다. 그 상태에서 밖으로 옮기도록 권하지 않는다. 실제 문제·코드·데이터·출력 로그·스크린샷·개인 링크·인증값·호스트명·실제 경로는 표에 넣지 않는다. 자동 전송하지 않는다.

아래는 빈 양식이다. 실제 확인한 사실로만 채워 대화에 출력하고, 이 공개 파일은 채우지 않는다. `통과 / 실패 / 미검증 / 막힘 / 해당 없음`을 구분한다. 브라우저는 허용 여부와 실제 실행 결과를 별도로 쓴다. `해당 없음`으로 미검증을 숨기지 않는다.

| 항목 | 실제 확인 결과 | 본시험에서 할 일 / 실패 시 대안 |
| --- | --- | --- |
| 공유 범위 | | |
| 공개 자료 가져오기 | | |
| START 명시 읽기 | | |
| OS·셸·제공 CLI·관련 런타임 | | |
| 작은 변경·실행·파일 보존 | | |
| 웹 서버 포트·바인딩·HTTP 확인 | | |
| 내장 Browser 직접 버튼 확인 | | |
| 로컬 Git 이력 관리 | | |
| 내부 이미지 전달 방법 확인 | | |
| 브라우저 테스트 허용·가용성·실행 | | |
| 체험 종료·예시 서술형 | | |
| 일반적인 막힘 | | |
| 다음 준비에서 보완할 것 | | |

가져오기는 clone / 아카이브 / raw / 불가 / 미검증 중 실제 결과를 쓴다. 도구명·버전도 공유 허용 범위 안에서만 적고, 모르면 미확인으로 둔다. 막힘은 네트워크 / 권한 / 설치 / 명령 지원 / 시간 부족 같은 범주로 요약한다. 과제 내용이나 실제 출력은 인용하지 않는다.

표 아래에 **가장 중요한 다음 행동 최대 3개**와 **본시험 재시작 한 문장**을 출력한다. 다음 행동에는 **“작업 화면에서 끝내지 말고, 제공 안내에 따라 직접 체험을 종료하고 예시 서술형까지 확인하세요. 서술형은 AI·복사·붙여넣기 없이 진행하세요.”**를 포함한다. 아직 진행하지 않았다면 표의 해당 항목은 `미검증 — 사용자가 다음 단계에서 직접 확인`으로 둔다. AI가 종료를 대신 누르거나, 문항·답안을 받아 해결·분석하거나, 내용을 외부로 옮기게 하지 않는다. 사용자가 확인했다고 알려준 경우에도 절차 확인 사실만 기록한다.

본시험 재시작은 새 환경에서 공식 안내·제공 CLI 확인 → 준비물 다시 가져오기 → START.md 적용 → 실제 과제 요청 순서를 포함한다. 본시험에는 사전체험 점검 전체를 반복시키지 않는다.

허용된 일반 환경 정보로 가져오기 대안·호환성·작업 지침을 개선할 수 있다. 실제 문제·기술 스택·제출물을 예측하거나 체험 성공을 본시험 호환성 보장으로 사용하지 않는다. 사전체험의 파일·설정·세션이 본시험에 유지된다고 가정하지 않는다. 실제 체험 코드·로그·작업 기록을 이 준비 저장소에 반영하지 않는다.
