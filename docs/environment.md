# 가져오기와 환경 확인

## 운영 전제

아래는 이 준비에 사용한 사용자 전달 공식 안내 요약이다. 원문 메일·개인 링크는 싣지 않는다. 최신 공식 안내와 실제 과제 지침이 우선하며, 불명확한 기능을 허용 또는 금지로 단정하지 않는다.

- 공개 지침·Skill·하네스·템플릿·코드를 가이드 범위에서 사용할 수 있다. 비공개 저장소와 외부 결과물로 과제 전체를 대체하는 방식은 사용하지 않는다.
- 공개 자료는 제공 환경의 AI를 통해 가져온다. 개인 PC 파일 직접 업로드에 의존하지 않는다. 사용한 공개 저장소는 2차 예선 결과 통지까지 공개 상태를 유지한다.
- 과제 수행 AI는 제공 Codex이며 제공 버전을 유지한다. 개인 API 키·외부 AI에 의존하지 않는다.
- Computer Use는 금지다. 브라우저·컴퓨터 자동 조작을 기본 구성에 넣지 않는다.
- 시험 자료·작업 결과를 외부로 전송하지 않는다. 사전체험·본시험에서는 모든 저장소의 git push를 하지 않으며, 테스트용·빈 커밋·`--dry-run` 및 API/CLI 원격 쓰기·업로드도 실행하지 않는다. 로컬 Git 이력 관리는 가능하다. 외부 검색에도 원문·코드·데이터 대신 일반화된 기술 용어만 쓴다.
- 후속 서술형은 AI와 복사·붙여넣기 없이 직접 작성한다.

## 별도 폴더로 가져오기

제공 터미널에서 공식 안내대로 `codex`를 실행한다. Codex에게 작업 경로·쓰기 가능한 범위·기존 파일을 먼저 확인하게 한 뒤 공개 URL과 검증한 revision을 알려준다. **가져오는 명령도 제공 AI가 실행**하게 한다.

저장 위치는 과제와 분리된 폴더가 우선이다. 접근 권한상 과제 안에 둘 수밖에 없다면 충돌하지 않는 전용 폴더를 사용하고, 제출 대상에서 분리한다. 기존 폴더가 있으면 무조건 덮어쓰거나 삭제하지 않고 내용·출처부터 확인한다. 별도 Git 저장소를 만들 수 있는지도 제공 환경에서 확인한다.

시작 위치가 홈(`~`)이면 제공 README·지정된 입력 경로에서 실제 과제 루트를 먼저 확인한다. 프로젝트가 아직 없고 새 폴더 작성이 허용되면 홈 아래의 별도 과제 폴더를 사용한다. 홈 전체를 재귀 조사·Git 초기화·stage하지 않는다. 제공 파일은 제자리에 보존하고 실제 수정 경로·참고 도구함 경로·제출 경로를 구분한다.

Codex가 사용할 수 있는 방법을 순서대로 선택한다. 명령과 옵션은 실제 OS·도구에 맞춘다.

| 방법 | 필요한 조건 | 성공 확인 / 실패 시 다음 행동 |
| --- | --- | --- |
| 공개 Git clone | Git, 공개 저장소 읽기 네트워크, 쓰기 가능한 새 경로 | 파일과 실제 `git rev-parse HEAD` 확인. 고정 revision이 다르면 그 상태로 검증했다고 하지 않음 |
| 공개 커밋의 소스 아카이브 | 허용된 HTTP 가져오기·압축 해제 기능 | 커밋 URL·파일 확인. 해제 전 경로가 목적 폴더 밖을 쓰지 않는지 점검 |
| 공개 raw 파일 읽기/저장 | 허용된 HTTP 읽기 기능 | 같은 revision의 `START.md`부터 읽고 필요한 playbook만 추가. HTML 오류 페이지를 Markdown으로 착각하지 않음 |
| 공개 웹 페이지 읽기 | 제공 AI에 웹 읽기 기능이 있고 해당 경로가 허용됨 | 실제 파일 본문을 읽었는지 확인. 검색 요약만 읽고 적용했다고 하지 않음 |
| 네트워크 접근 불가 | 위 방법 모두 사용할 수 없음 | 가져오기 실패를 기록하고 아래 최소 흐름으로 진행. 인증·차단 우회나 개인 파일 업로드로 바꾸지 않음 |

이미 일부 파일이 내려왔다면 성공한 파일과 실패한 파일부터 구분한다. 같은 실패를 근거 없이 반복하지 말고 가능한 다음 방법으로 옮긴다. Git clone에는 로그인이나 개인 토큰이 필요하다고 미리 가정하지 않는다.

**아무 파일도 못 가져왔을 때 사용할 최소 요청**

```text
제공 README·AGENTS.md와 현재 코드를 읽고 필수 요구와 중요한 미확정 질문을 정리해라.
세팅만 요청받았다면 확인 항목·현재 상태·다음 행동 표를 출력하고 과제를 수정하지 마라.
기존 코드부터 재사용 가능성을 살피고 허용된 검색이 가능할 때만 일반 기술어로 공개 구현을 확인해라.
실제 작업·점검 요청을 받았을 때만 허용된 작은 변경을 구현하고 프로젝트의 실행 방법으로 검증해라.
사전체험 점검 요청을 받으면 clone 실패와 별개로 작은 수정→저장→실행 확인을 해라. 웹이면 실제 포트·바인딩을 확인하고 사용자가 내장 Browser에서 직접 버튼을 누르게 안내해라.
캡처는 시도하지 말고 허용된 내부 이미지 전달 방법을 질문하게 해라. 사전체험 점검 종료 전 요약 후 사용자가 직접 체험 종료→예시 서술형까지 확인하게 안내하되 서술형에서는 AI·복사·붙여넣기를 사용하지 않는다.
실행 결과와 미검증·남은 한계를 구분해 과제 환경 안에 기록해라.
로컬 Git으로 자신의 변경만 관리하고 제공 파일·Codex 버전을 보존해라. 외부 AI·Computer Use·외부 전송·모든 push·원격 쓰기는 사용하지 마라.
```

이 요청은 도구함을 읽었다는 증거가 아니다. 개인 파일이나 긴 준비물을 붙여넣는 대안도 아니다. 입력 자체의 허용 범위는 공식 안내에 따른다.

## 도구함 지침과 스킬 설치 구분

[현재 공식 문서](https://developers.openai.com/codex/guides/agents-md)에 따르면 Codex는 시작할 때 전역 및 프로젝트 경로의 `AGENTS.md` 계열을 발견하며, 현재 작업 디렉터리·override 파일·크기 제한의 영향을 받는다. **옆 폴더를 clone했다고 그 지침이 현재 과제에 자동 적용되는 것은 아니다.** 제공 버전의 동작은 별도로 확인해야 한다.

이 저장소의 `AGENTS.md`는 도구함 유지보수용이다. 과제에는 `START.md`의 실제 경로를 명시해 읽게 한다. 읽은 경로와 핵심 규칙을 짧게 확인하고 실제 행동으로 검증한다. AI가 “적용했다”고 말한 것만으로 자동 발견을 입증하지 않는다. 기존 지침을 바꾸거나 전역 설정·override를 추가할 필요는 없다.

스킬은 별도다. 세팅 때 [스킬 설치](skills.md)에 따라 원본 Caveman과 explain-work를 Codex 사용자 스킬 경로에 실제 설치한다. 설치 후 `/skills`에서 선택하거나 `$caveman`, `$explain-work`로 호출한다. [공식 Skill 문서](https://developers.openai.com/codex/skills)의 설치·발견 방식을 따르며, 단순히 옆 폴더의 파일을 읽는 것으로 정상 설치를 대신하지 않는다. 파일 설치와 목록 확인 상태는 구분해 알린다.

## 본시험에서 필요한 만큼 확인

- **OS·셸·CLI:** 실제 OS 종류·사용 셸을 먼저 확인한다. Linux/Debian 계열이면 `/etc/os-release`의 OS 식별 정보와 사용 가능한 명령을 확인하고 Linux 경로·셸 문법을 쓴다. Debian이라는 이유로 sudo·apt 설치·특정 런타임이 된다고 가정하지 않는다. `codex --version`, `codex --help`로 제공 버전·옵션을 읽으며 업데이트·재설치를 하지 않는다. 권한은 아래 선택 사항을 따르고 자동 변경하지 않는다.
- **검증 기본 경로:** Codex가 브라우저 화면을 직접 볼 수 있다고 가정하지 않는다. 로컬 테스트·HTTP 응답과 사용자의 내장 Browser 수동 확인을 조합한다. 명령 실행 성공·다운로드 성공·실제 UI 확인은 따로 판정한다. 포괄적인 “확인됨” 보고만으로 개별 항목을 통과 처리하지 않는다.
- **이미지:** 캡처를 직접 시도하지 않는다. 먼저 공식 안내·질문 창구에 **“허용된 내부 이미지 전달 방법이 있나요? 제공 Codex에 전달하는 절차는 무엇인가요?”**를 확인하도록 안내한다. 안내된 방식의 무해한 제공 이미지로만 내용 읽기를 확인한다. [현재 CLI 문서](https://developers.openai.com/codex/cli/reference)의 `-i`/`--image` 지원은 제공 환경의 허용 근거가 아니며, 허용 방식과 제공 버전 도움말이 확인된 뒤에만 사용한다. 파일명만 읽힌 것을 이미지 이해로 처리하지 않는다. 개인 PC 업로드·외부 OCR·캡처 도구로 우회하지 않는다. 방법이 없거나 미확인이면 제공 텍스트·사용자의 설명으로 진행하고 이미지 확인은 미검증으로 남긴다.
- **IDE 확장:** 사용 허용 여부 미확인. 기본은 공식 안내의 CLI다.
- **추가 MCP:** 모든 MCP가 금지라는 뜻은 아니다. 필요성·허용 범위·외부 전송·인증·실행 의존성을 확인하기 전에는 구성하지 않는다. 대안은 제공 파일과 로컬 명령이다.
- **내장 병렬 작업:** 허용·지원과 독립 작업이 확인될 때만 사용한다. 수를 강제하지 않는다. 대안은 순차 작업이다.
- **브라우저 관련 테스트:** 직접 화면 확인 기능을 찾아 설치·재시도하는 것을 기본 작업으로 삼지 않는다. 필요하고 허용·가용성이 확인된 경우에만 아래 조건 분기를 쓴다. 모든 브라우저 테스트가 금지됐다고 추론하지 않는다.

### 권한 옵션: 사용자가 선택할 때만

승인 질문을 끄는 설정과 샌드박스 범위는 별개다. 제공 버전이 지원하고 해당 환경에서 사용 가능한 경우, 아래 명령은 승인 질문 없이 Codex의 샌드박스를 해제한 세션을 시작한다.

```bash
codex -a never -s danger-full-access
```

명령이 확인 없이 넓은 파일·네트워크 범위에서 실행될 수 있다. `-a never`만으로 권한이 늘어나는 것은 아니며, 이 조합도 OS 권한·관리자 정책·주최 측 제한을 제거하지 않는다. 적용이 거부되면 제한을 우회하지 않는다. 이미 실행 중인 세션의 권한을 프롬프트로 바꿨다고 주장하지 않는다.

세팅 과정에서 이 명령을 자동 실행하거나 전역 config를 덮어쓰지 않는다. 사용자가 선택할 때 제공 `codex --help`와 공식 안내를 확인해 실행한다. 권한 선택과 별개로 이 도구함의 push·외부 전송·Computer Use 금지 및 캡처 금지 지침은 유지한다. [공식 CLI 옵션](https://learn.chatgpt.com/docs/cli/reference).

### 브라우저 자동화를 사용할 조건

| 확인 상태 | 행동 |
| --- | --- |
| 해당 도구·방식이 공식적으로 허용됨 + 실행 가능 | UI 과제에서 유용하면 사용한다. 핵심 사용자 흐름, 오류·빈 상태, 목표 화면 크기와 결과를 실제로 확인한다. 이미 제공된 도구·테스트를 우선한다. |
| 허용은 확인됐으나 도구·런타임·브라우저가 없음 | 필요한 설치·다운로드의 허용, 시간과 의존성을 확인해 이점이 있으면 최소 구성한다. 설치 자체가 목적이 되지 않게 하고, 불가하면 아래 대안으로 진행한다. |
| 금지됨 또는 허용 범위가 미확인 | 해당 자동화는 실행하지 않는다. 필요하면 공식 창구로 확인하고, 독립적인 로컬 검사·허용된 수동 확인을 진행한다. |

Playwright 같은 도구 이름이나 “테스트”라는 명칭 자체가 허용 근거는 아니다. 사용할 기능, 로컬 실행인지, 외부 데이터 전송·인증·다운로드가 있는지를 확인한다. 직접 캡처뿐 아니라 자동 스크린샷·영상·화면 캡처가 포함된 추적도 실행하지 않는다. 캡처 없는 실행을 확인할 수 없으면 해당 테스트를 생략하고 로컬 검사·사용자 수동 확인으로 전환한다. 시험 자료·결과를 외부 테스트 서비스에 보내지 않고 허용된 로그는 과제 환경 안에만 둔다.

대안은 기존 단위·컴포넌트 검사, 로컬 HTTP 응답 확인, 허용된 사람의 브라우저 수동 확인, 제공 Codex가 읽을 수 있는 로컬 이미지다. 각각 확인한 범위만 증명한다. 빌드나 HTTP 200만으로 화면·상호작용까지 통과했다고 쓰지 않는다.

### 웹 실행: 포트와 내장 Browser

1. 제공 README·실행 스크립트·환경의 포트 안내를 먼저 확인한다. 지정 포트가 있으면 우선하고, 없으면 제공 환경에서 허용된 사용 가능한 포트 하나를 고른다. 특정 프레임워크나 포트 번호를 미리 강제하지 않는다.
2. 실행할 서버의 실제 host·port 설정을 확인한다. 제공 Browser가 컨테이너/작업 환경 밖에서 연결하는 구조라면 안내에 맞춰 `0.0.0.0`으로 바인딩해 접근 가능하게 한다. 공식 환경이 다른 바인딩을 요구하면 그 안내를 따른다. `0.0.0.0`은 수신 주소 설정이며 사용자에게 열어볼 주소로 그대로 제시하지 않는다.
3. 서버를 실행하고 실제 listen 주소·포트를 확인한다. 요청한 포트가 사용 중이면 도구가 다른 포트로 바꿀 수 있으므로 로그·프로세스·로컬 요청으로 확인한다. 다른 프로세스를 무작정 종료하지 않는다. 접속을 위해 외부 터널·공개 배포·방화벽 전체 해제를 사용하지 않는다.
4. **작은 변경을 파일에 저장한 뒤** 실제 응답에 반영됐는지 확인한다. 필요하면 프로젝트 방식에 맞춰 다시 빌드·시작한다. 로컬 HTTP 응답과 변경된 내용까지 확인하며, 서버 시작 메시지만으로 통과 처리하지 않는다.
5. 제공 환경의 내부 미리보기/포트 연결 절차로 얻은 **내장 Browser용 주소**와 눌러볼 버튼·예상 결과를 사용자에게 알려준다. 사용자가 직접 열어 입력·버튼·결과를 확인한다. AI가 내장 Browser를 자동 조작하거나 캡처하지 않는다. 아직 확인 답이 없으면 `HTTP 통과 / Browser 미검증`처럼 분리하고, 사용자가 확인해 주면 `사용자 수동 확인`을 근거로 표시한다.
6. 기존 웹 프로젝트가 없으면, 체험에서 별도 샘플이 허용될 때만 이미 제공된 런타임으로 작은 샘플을 사용한다. 비웹 과제에 억지로 UI나 새 프레임워크를 추가하지 않는다. 종료 시 자신이 띄운 임시 서버의 정리 여부도 제공 안내에 맞춰 확인한다.

여기 나열한 기능은 별도 설치 추천 목록이 아니다. 필요성이 확인되지 않은 기능은 추가하지 않는다. 사전체험의 파일·설정·세션이 본시험에 유지된다고 가정하지 않고, 본시험에서도 새 환경에서 가져오기부터 반복한다.

push 금지는 에이전트가 따라야 할 운영 지침이다. OS·네트워크 수준의 기술적 차단을 설치했다는 뜻은 아니다. 제공 프로젝트의 hook·remote·전역 Git 설정을 임의로 변경하지 않는다.
