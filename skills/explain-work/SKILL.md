# 내가 한 작업 설명하기

실제 선택과 결과를 사용자가 자기 말로 설명하도록 돕는다. 사전 연습 또는 AI 사용이 허용된 작업 단계에서 사용한다. **AI 사용이 금지된 실제 후속 서술형에 들어갔다면 이 연습을 멈춘다.** 실제 문항·답안을 받아 작성·교정하지 않는다.

## 실제 작업에서 시작

1. 현재 대화와 허용된 로컬 작업 기록·관련 diff·실행 결과에서 중요한 선택 하나를 찾는다. 전체 저장소를 다시 조사하거나 외부로 자료를 보내지 않는다. 기록이 없다면 다룰 작업을 한 문장으로 물어본다. 실제 과제 자료를 준비용 공개 저장소에 넣지 않는다.
2. 다음 사실표를 최대 5행으로 짧게 채운다. 실제 근거가 없는 칸은 `미확인`으로 둔다. 코드에서 읽은 동작, 사용자가 말한 의도, 직접 실행한 결과를 구분한다.

| 돌아볼 것 | 실제 사실·근거 | 사용자가 설명할 부분 |
| --- | --- | --- |
| 요구·질문 | 확인한 요구와 답, 남은 가정 | 무엇을 해결하려 했고 무엇을 확인했나 |
| 선택·재사용 | 실제 채택한 구현과 검토 기록 | 왜 선택했고 어떤 대안과 비교했나 |
| AI와 내 역할 | 대화·변경에서 확인되는 역할 | AI에 무엇을 맡겼고 내가 무엇을 판단했나 |
| 문제·검증 | 실제 실패·수정·재실행 결과 | 무엇을 근거로 동작한다고 판단하나 |
| 한계 | 미완료·미검증·남은 위험 | 어디까지 확인했고 다음에는 무엇을 할 건가 |

이 표는 정답·채점표·제출용 문단이 아니다. 인터뷰에서 언급한 역량을 확정 평가 기준으로 쓰지 않는다. “좋은 설계니까 그 이유로 골랐을 것”처럼 선택 동기·검토한 대안·사용자의 기여를 추정하지 않는다. 이유를 모르면 사용자에게 묻는다. HTTP 성공을 UI 검증으로 바꾸지 않는다.

## 하나씩 설명 연습

- `서술형 대비해` / `설명 연습해`: 위 표를 보여주고 가장 중요한 질문 **하나만** 한다. 추천 답변이나 완성 문단을 먼저 주지 말고 사용자의 답을 기다린다.
- 답을 받으면 근거와 맞는 부분, 근거가 부족하거나 설명이 빠진 부분을 짧게 짚는다. 사실 오류는 해당 기록으로 확인하고, 사용자의 실제 의도는 대신 정하지 않는다.
- 필요한 다음 질문 하나로 이유와 증거를 연결한다. 예: “그 선택이 맞는지 무엇으로 확인했나요?” 사용자가 모르면 관련 코드·검증을 짧게 설명한 뒤 자기 말로 다시 말해 보게 한다. 허위 성공·그럴듯한 회고를 만들지 않는다.
- 한 번에 중요한 선택 한두 개면 충분하다. 사용자가 중단하거나 작업으로 돌아가면 끝낸다. 연습 종료를 곧 이해 완료·시험 준비 완료라고 판정하지 않는다.
- `서술형 대비 정리만 해`: 사실표와 다시 확인할 부분만 보여주고 질문을 시작하지 않는다.

기록은 필요할 때만 현재 과제 환경의 허용된 로컬 경로에 남긴다. 실제 서술형 단계에서는 AI·복사·붙여넣기 없이 사용자가 직접 작성한다. 이 Skill을 읽었다는 사실만으로 자동 발견·설치가 됐다고 주장하지 않는다.
