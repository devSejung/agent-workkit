# 실패에서 최소 수정까지

**읽는 때:** 테스트 실패, 실행 오류, 기대와 다른 결과, 간헐적인 문제.

1. **재현:** 정확한 명령·작업 디렉터리·입력·기대 결과·실제 오류·종료 상태를 확인한다. 가장 작은 재현을 찾는다. 원래 있던 실패인지 이번 변경으로 생겼는지도 구분한다.
2. **원인 근거:** 오류 메시지, 관련 코드 경로, 입력·출력 경계, 설정과 최근 변경을 읽는다. 추측으로 여러 곳을 한꺼번에 고치지 않는다.
3. **가설 하나:** 원인 후보 하나와 이를 구분할 관찰·명령을 정한다. 실패한 가설은 버리고 새 증거로 좁힌다. 설치·네트워크 문제와 기능 결함을 구분한다.
4. **최소 수정:** 확인된 원인을 다루는 작은 변경을 한다. 기존 계약을 유지하고 무관한 리팩터링을 섞지 않는다.
5. **재검증:** 원래 실패한 사례를 다시 실행한 뒤 영향받는 기존 동작을 확인한다. 실패를 숨기려고 검증을 삭제하거나 기대값을 실제 오류에 맞춰 낮추지 않는다.

같은 도구 실패를 새 근거 없이 반복하지 않는다. 동일 실패 두 번 또는 10분 동안 진전이 없으면, 확인한 상태와 불확실한 쓰기를 먼저 정리하고 허용된 다른 방법으로 전환한다. 인증·신뢰·권한 제한을 우회하지 않는다.

환경 제약으로 실행하지 못했다면 `막힘`과 이유, 실행해 보지 않았다면 `미검증`으로 남긴다. 오류가 사라졌다는 주장에는 실제 재실행 결과가 필요하다. 간헐 오류는 한 번 통과만으로 완치라고 쓰지 않는다.

**남길 것:** 실제 증상 → 원인 근거 → 수정 → 재실행 결과. 긴 사고 과정이나 그럴듯한 회고를 만들지 않는다.
