# 선택·배정·최적화 문제 다루기

**읽는 때:** 여러 후보 중 선택하거나 자원을 배정하며, 정확성·품질·계산 시간을 설명해야 할 때. 특정 알고리즘·솔버·서비스를 선설치하라는 지침이 아니다.

## 코딩 전에 작은 모델로 설명

다음 다섯 항목을 실제 요구와 데이터로 짧게 정리한다. 수식은 설명에 도움이 될 때만 쓴다.

| 항목 | 확인할 내용 |
| --- | --- |
| 입력 | 개체 수, 식별자·관계, 단위·시간 기준, 누락·중복·예외, 실제 측정값과 추정값 |
| 결정 | 무엇을 선택·배정·변경하며, 무엇은 이미 정해져 있는가 |
| 강제 제약 | 유효한 결과가 반드시 지켜야 하는 조건과 그 출처 |
| 목표·선호 | 무엇을 줄이거나 늘리는가. 목표가 충돌하면 우선순위는 무엇인가 |
| 결과와 검증 | 결과를 어떻게 사용하며 제약 위반·누락·품질·실행 시간을 어떻게 확인하는가 |

주기·대상별 규칙은 해당 입력에 적용해 모델을 만든다. 선호를 강제 조건으로, 강제 조건을 임의의 벌점으로 바꾸지 않는다. 비용·우선순위·가중치가 없으면 확인하거나 가정을 표시한다. 상한·비용이 없어서 무제한 자원 투입이 답이 되는 모델은 실제 업무 목표와 맞는지 확인한다.

## 비교할 기준선부터 실행

1. [기존 구현](reuse.md)에서 맞는 부품을 찾는다. 먼저 설명 가능한 간단한 규칙으로 유효한 기준 결과를 만든다. 모든 입력에 유효한 결과를 만들 수 없다면 누락과 이유도 결과에 포함한다.
2. **결과 생성과 결과 검증을 분리**한다. 별도 검사에서 필수 제약·입력 보존·중복 배정·처리되지 않은 대상을 확인하고, 품질 지표는 따로 계산한다. 작은 사례는 손으로 기대 결과를 확인한다.
3. 후보를 일부만 남기거나 근사값을 쓰면 비용 절감 효과와 제외되는 가능성을 설명한다. 대리 지표로 고른 후보가 실제 평가에서도 좋은지는 별도 확인한다. 가능한 후보를 놓치는 반례와 후보 범위를 넓혔을 때의 차이를 작은 사례에서 확인한다.
4. 기준선의 제약 충족·품질·규모가 부족할 때 정확한 탐색, 개선 휴리스틱, 솔버를 비교한다. 이미 실행되는 기준선은 남겨 둔다. 솔버를 쓴다는 이유만으로 모델이 올바르거나 결과가 최적이라고 하지 않는다.

일반적인 후보는 규칙·탐욕법·국소 개선, 매칭·흐름 알고리즘, LP/MILP, 제약 프로그래밍 등이다. 실제 변수·제약 구조와 유지할 수 있는 코드, 설치·검증 비용으로 고른다. 도구 선택이 목적이 되지 않게 한다.

## 데이터 규모와 외부 호출

- 코딩 초기에 입력 개수와 후보 조합·호출 수를 계산한다. 전체 조합인지, 개체당 일부 후보인지 구분한다. 각 호출의 지연·쿼터·재시도까지 감안해 작은 표본으로 시간을 잰다.
- 반복 계산은 같은 입력·규칙·버전에 대해 재사용한다. 중복 제거, 로컬 캐시, 지원되는 일괄 처리, 제한된 동시 실행 중 효과가 있는 것만 선택한다. 실제 입력 규모에서도 실행 시간을 확인한다.
- 실패한 호출·없는 데이터·아직 계산하지 않은 값을 유효한 0이나 성공으로 바꾸지 않는다. 부분 결과와 이유를 남긴다. 변경된 입력·조건에 오래된 캐시를 적용하지 않는다.
- 시험 자료를 외부 서비스에 보내지 않는다. 연동이 필요한 경우 공식 허용 범위와 데이터 경계를 먼저 확인한다. 허용된 시험용 입력의 연결 점검과 실제 데이터 전송은 구분한다.

## 결과 상태를 정확히 말하기

탐색에는 남은 시간에 맞는 실행 한도를 두고 실제 종료 상태·목적값·제약 위반·실행 시간을 기록한다. 가능하면 기준선과 같은 입력으로 비교한다.

| 관찰 | 보고 |
| --- | --- |
| 유효한 결과를 찾음 | 제약 충족 범위를 말한다. 최적 증명과 구분한다. |
| 최적 상태를 반환함 | 사용한 모델·시간/오차 설정과 함께 해석한다. 라이브러리의 상태 정의를 확인한다. |
| 시간 내 결과를 못 찾음 | 미발견·시간 제한을 기록한다. 불가능하다고 단정하지 않는다. |
| 불가능 상태를 반환함 | 입력·단위·변수 범위·모델 오류와 충돌 제약부터 확인한다. 현실의 불가능과 모델의 불가능을 구분한다. |

진단을 위해 조건을 완화해 얻은 결과는 원래 요구의 유효한 결과로 제출하지 않는다. 빈 입력·경계값·잘못된 데이터·해가 없는 사례·대표 규모에서 확인할 범위를 정한다. 사용자가 입력 하나에서 결과가 나오는 이유와 남은 한계를 설명할 수 있어야 한다.
